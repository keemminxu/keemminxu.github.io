# 은크크 Pick 디지털 뽑기 페이지 — 설계

날짜: 2026-11-16
행사: 2026-11-21(토) 11:00–16:00, 은평 대조시장 참여 점포 10곳 / 굿즈 수령 부스: 서울청년센터 은평 B동 2층 모여방

## 목표

참여 점포에서 5,000원 이상 구매한 영수증 1장당 1회, 부스에서 3D 캡슐 가챠 머신을 돌려 수건·컵·장바구니 중 하나를 받는다. 머신 안에는 **남은 굿즈 수량만큼 캡슐이 실제로 들어 있고**, 하나 뽑을 때마다 캡슐 하나가 실제로 빠져나온다. 캡슐이 열리면 이펙트와 함께 당첨 굿즈의 3D 메시(Meshy image-to-3D)가 나타난다.

## 범위

- 블로그(GitHub Pages) 정적 페이지 1개 + 기존 vendored three.js 0.185.1. 빌드 단계 없음.
- 참가자 정보 입력(항목은 설정으로 켜고 끔) + 개인정보 수집·이용 동의.
- 남은 수량 비례 추첨, 남은 수량 상시 표시.
- 관리자 패널(PIN): 설정, 재고 수정, 기록 CSV, 개인정보 파기, 마지막 뽑기 취소, 초기화.

## 비범위

- 서버·DB, 여러 기기 간 재고 동기화(부스 기기는 1대).
- 참가자 각자 폰으로 접속하는 방식, 1인 횟수 제한(포스터 기준 제한 없음).
- 점포별(1~10번) 영수증 기록.
- 오프라인 동작용 Service Worker.

## 1. 운영 환경

- 부스 노트북 1대 + 외부 모니터/TV **미러링**. 해상도 기준 1920×1080 가로.
- 브라우저: 노트북의 Chrome(최신). 조작은 노트북 마우스/트랙패드와 키보드.
- 데이터는 이 노트북 브라우저의 localStorage에만 저장한다. 행사 후 CSV로 내보내고 파기한다.

## 3. 데이터 (`store.js`)

localStorage 키 `eunkk-pick-v1`, 값은 JSON 하나.

```js
{
  settings: {
    title: "은크크 Pick",
    pin: "0000",                       // 실수 방지용. 보안 장치 아님
    fields: { name: false, phone: false, birth: false },
    consent: { org: "", purpose: "", retention: "", contact: "" },
    sound: true
  },
  stock: {
    towel: { label: "수건",     total: 0, left: 0 },
    cup:   { label: "컵",       total: 0, left: 0 },
    bag:   { label: "장바구니", total: 0, left: 0 }
  },
  draws: [ { no: 1, at: "2026-11-21T11:03:12+09:00", prize: "cup",
             name: "", phone: "", birth: "", shown: true } ]
}
```

- **URL 파라미터** `?towel=30&cup=20&bag=25`: 저장된 상태가 **없을 때만** `total`과 `left`의 초기값으로 쓴다. 저장된 상태가 있으면 무시하고, HUD 구석에 "저장된 재고를 사용 중" 표시를 잠깐 띄운다. 행사 도중 북마크로 다시 열어도 재고가 되돌아가지 않게 하기 위함.
- 저장 상태도 파라미터도 없으면 첫 화면에서 관리자 패널을 열어 수량 입력을 요구한다.
- `commitDraw(prize, entry)`: `left` 1 감소 + `draws`에 추가(`shown: false`) + 즉시 저장. 저장이 실패하면 예외를 던지고 연출을 시작하지 않는다.
- `markShown(no)`: 결과 화면을 보여 준 뒤 `shown: true`.
- `undoLast()`: 마지막 기록 삭제 + 해당 경품 `left` 1 복구.
- `purgePersonal()`: 모든 기록의 `name/phone/birth`를 빈 문자열로. 시각·경품은 남긴다.
- `resetAll()`: 기록 삭제 + `left = total`.
- `toCSV()`: UTF-8 BOM + `순번,시각,경품,이름,휴대폰,생년월일`. 꺼진 항목의 열은 빼지 않고 빈 값으로 둔다(열 구성 고정).

## 4. 뽑기 흐름 (상태 머신, `main.js`)

```
SETUP ─(재고 입력)→ LOCKED ─(입장)→ READY ─(손잡이 1바퀴)→ COMMIT → DISPENSE → OPEN → RESULT ─(다음 참가자)→ LOCKED
                                                                                             └(전부 소진)→ SOLDOUT
```

- **LOCKED**: 머신은 대기 애니메이션(캡슐이 가볍게 출렁). 화면 아래 버튼 하나:
  - 수집 항목이 하나라도 켜져 있으면 "참가하기" → 정보 입력 + 동의 오버레이. 휴대폰·생년월일 입력칸은 `type="password"` + `inputmode="numeric"`, 아래에 "끝자리 1234"만 표시(미러링 화면에 번호가 노출되지 않게). 형식 검사 후 "뽑으러 가기"로 READY.
  - 모두 꺼져 있으면 "영수증 확인 완료" 버튼(스태프가 누름) → READY.
- **READY**: 손잡이에 하이라이트와 "돌려 주세요" 안내. 손잡이를 시계 방향으로 끌어 돌린다(포인터 각도 누적, 역방향 무시). 45°마다 래칫 소리와 머신 흔들림, 캡슐 교반. 스페이스/엔터를 누르면 자동으로 1바퀴(스태프 보조용).
- **COMMIT**: 1바퀴(360°)가 되는 순간 `draw.js`로 경품을 정하고 `store.commitDraw`로 저장한다. **연출 전에 저장**하므로 연출 중 새로 고침·오류가 나도 재고와 기록이 맞는다. 단 화면 오른쪽 남은 개수는 RESULT가 뜬 뒤에 줄인다(연출 중에 줄면 어떤 경품인지 미리 보인다).
- **기본 재고**: 저장본도 주소 수량도 없으면 경품마다 100개로 시작하고, 실제 수량은 관리자 화면에서 맞춘다. SETUP 안내는 총수량이 모두 0일 때만 뜬다.
- **DISPENSE**: 배출구에 가장 가까운 캡슐을 물리에서 떼어 내 키네매틱 경로(배출구 → 슈트 → 받침 트레이)로 굴린다. 캡슐 색은 경품과 무관하게 무작위라 열기 전까지 무엇인지 모른다.
- **OPEN**: 카메라가 트레이로 다가가고, 캡슐이 떠올라 흔들리다 반으로 갈라진다 → 이펙트(§6) → 경품 메시가 커지며 회전.
- **RESULT**: "수건 당첨! 부스에서 받아 가세요" 카드 + HUD 수량 갱신, `markShown`. "다음 참가자" 버튼(또는 20초 뒤 자동)으로 LOCKED.
- **SOLDOUT**: 남은 수량 합이 0이면 "모든 굿즈가 소진됐어요" 화면. 관리자 패널에서 재고를 늘리면 LOCKED로 돌아간다.
- **새로 고침 복구**: 로드 시 마지막 기록이 `shown: false`면 연출 없이 그 결과 카드부터 보여 준다.
- 연출 중(COMMIT~OPEN)에는 모든 입력을 잠근다.

## 5. 추첨 (`draw.js`)

```js
pickPrize(stock, rand = Math.random) // → "towel" | "cup" | "bag" | null
```

- 확률은 `left_i / Σleft`. `left`가 0인 경품은 나오지 않는다. 합이 0이면 `null`.
- `rand`를 주입받아 테스트에서 경계값(0, 0.999…)과 분포를 검증한다.
- 캡슐 하나하나에 경품을 미리 정하지 않는다. 어떤 캡슐이 나오든 경품은 `pickPrize`가 정한다. 캡슐 수가 남은 수량과 같고 캡슐 색이 무작위이므로, 실제 뽑기통과 확률이 같다.

## 6. 3D 무대 (`stage.js`, `physics.js`)

**머신** (three 기본 도형, 외부 모델 없음)
- 받침: 둥근 모서리 상자, 짙은 초록. 앞면에 "은크크 Pick" 로고 판(캔버스 텍스처).
- 돔: 구 상단부, 투명 재질(`opacity` + 환경 반사, `transmission`은 쓰지 않음 — 비용).
- 손잡이: 노란 원판 + 손잡이 막대. 배출구와 덮개, 앞쪽 받침 트레이.

**캡슐** (`InstancedMesh` 2개: 색 반구 + 흰 반구)
- 개수 = `Σleft`, 렌더 상한 200개. 200개를 넘으면 200개만 넣고, 하나가 빠질 때 남은 수량이 아직 200 이상이면 돔 위에서 하나를 떨어뜨려 채운다.
- 반지름은 개수에 맞춰 돔이 절반쯤 차도록 `r = R · ∛(φ / N)`(φ≈0.35)로 정하고 최소·최대로 제한한다.
- 색 반구는 포스터 카테고리색(분홍·초록·주황·노랑)에서 무작위.
- 관리자 패널의 재고 수정·뽑기 취소·초기화로 `Σleft`가 바뀌면, 캡슐 수를 다시 맞춘다(늘면 돔 위에서 떨어뜨리고, 줄면 위쪽 캡슐부터 뺀다).

**물리** (자체 구현, 의존성 없음)
- 고정 스텝 1/60, Verlet 적분, 반복 4회 위치 보정: 구-구 겹침 해소, 돔 내부 구속(중심 C, 반지름 R−r), 바닥 평면.
- 교반: 손잡이가 돌 때 돔 바닥 근처 캡슐에 회전 방향 접선 속도 + 약한 위쪽 충격.
- 캡슐 회전은 이동 속도로 구한 굴림 회전을 누적해 표현.
- N=200에서 쌍 검사 약 2만 회/스텝으로 충분히 가볍다. 부족하면 균일 격자 분할을 넣는다.

**이펙트** (후처리 없이 가산 혼합 스프라이트·인스턴스로)
- 캡슐 개봉 순간: 흰 섬광 스프라이트 확대 후 사라짐, 회전하는 빛줄기 스프라이트(캔버스로 그린 텍스처), 바닥 발광 링.
- 색종이: `InstancedMesh` 사각형 300장, 포스터 색, 중력 + 회전, 3초 뒤 사라짐.
- 경품 주변 반짝이: `Points` 소량, 위아래로 흔들림.
- 효과음: Web Audio로 합성(래칫 딸깍, 캡슐 굴러가는 소리, 개봉 팡, 짧은 팡파르). 설정에서 끔.

**경품 메시**
- GLB 로드 후 바운딩 박스로 중심 맞추고 같은 크기로 정규화.
- 로드 실패 시 경품 이름을 그린 카드 평면(캔버스 텍스처)으로 대체. 이펙트는 그대로 재생된다.

**성능**
- 목표: 노트북 내장 GPU에서 1920×1080 60fps. `pixelRatio = min(devicePixelRatio, 1.5)`.
- 그림자는 그림자 맵 대신 바닥의 블롭 그림자 텍스처.
- WebGL 생성 실패 시 3D 없이 HUD + 결과 카드만으로 행사를 진행할 수 있게 한다(뽑기 버튼으로 대체).

## 7. 경품 메시 파이프라인

1. (사용자) 실물 굿즈 사진으로 Meshy image-to-3D → GLB 3개 전달. 수건은 접어서 띠를 두른 모양, 장바구니는 펼친 모양으로 촬영 권장.
2. `gltf-transform`으로 최적화: 단순화(약 2만 삼각형 이하), 텍스처 1024px, meshopt 압축. 목표 파일당 1MB 이하.
   - Windows에서 텍스처 명령이 실패하면 sharp 이중 설치 문제 → overrides로 단일화(기존 메모 참고).
3. `assets/glb/pick/`에 배치. 디코더는 이미 vendored된 `jsm/libs/meshopt_decoder.module.js` 사용.

**GLB 전달 마감: 11/18(수) 오전.**

## 8. 관리자 패널 (`ui.js`)

- 여는 법: 화면 구석의 작은 톱니 버튼 또는 `Ctrl+Shift+A` → PIN 입력.
- 항목: 행사 제목, PIN 변경, 수집 항목 켜고 끄기, 동의 문구(수집 주체·목적·보유 기간·문의처), 효과음, 경품별 남은 수량 수정(`total`도 함께 보임), 기록 표와 CSV 내보내기, 마지막 뽑기 취소, 개인정보 파기, 전체 초기화.
- 파괴적 작업(파기·초기화·취소)은 패널 안에서 한 번 더 확인 버튼을 누르게 한다.

## 9. 오류 처리

| 상황 | 동작 |
|---|---|
| localStorage 저장 실패 | 빨간 경고 띠 + 뽑기 잠금. 재고 추적이 안 되는 상태로 진행하지 않는다 |
| GLB 로드 실패 | 경품 이름 카드로 대체 |
| WebGL 미지원 | 2D 모드(HUD + 버튼 + 결과 카드) |
| 남은 수량 0 | SOLDOUT 화면 |
| 연출 중 입력 | 무시 |
| 연출 중 새로 고침 | 로드 시 `shown: false` 기록의 결과 카드 표시 |

## 10. 검증

- `node scripts/pick-test.mjs`
  - `pickPrize`: 재고 0 제외, 합 0이면 null, 경계값, 10만 회 분포가 비율 ±1%p.
  - `store`: 파라미터는 저장 상태 없을 때만 적용, commit/undo의 재고·기록 일관성, purge 후 개인정보 없음, CSV 헤더·BOM·쉼표 이스케이프.
  - `physics`: 200개 구가 일정 시간 후 돔 밖으로 나가지 않음, 겹침이 허용치 이하.
- 로컬 headless Chrome(playwright-core)으로 1920×1080 스크린샷: LOCKED, READY, OPEN, RESULT, SOLDOUT, 관리자 패널. 콘솔 오류 0.
- 11/20(금) 실제 노트북 + TV로 리허설: 프레임, 글자 크기, 효과음 크기, 새로 고침 복구, CSV 내보내기.

## 13. 화풍 개정: 포스터 손그림 툰 (2026-11-16 추가)

첫 구현(기본 도형 + 파스텔 단색 + Phong 유리 + 가산 스프라이트 이펙트)이 툰도 실사도 아닌 어중간한 인상이라는 피드백을 받아, 포스터 손그림풍 툰으로 통일했다.

- 공용 `toon.js`: 3단 셀 램프(소품 `[0.5, 0.78, 1]`, 경품 `[0.72, 0.9, 1]`), 볼록 물체용 잉크 외곽선(축별 확대 뒷면), 경품용 법선 외곽선(meshopt 양자화 위치를 Float32로 풀고 정점 병합 후 법선 방향으로 밀기), 툰 유리 셰이더(가장자리 잉크선 + 흰 하이라이트 띠), 텍스처의 어두운 인쇄만 뽑는 데칼.
- 머신: 노랑 받침·초록 테두리·주황 손잡이·분홍 덮개, 앞판에 포스터의 은크크Pick 도장(`assets/images/eunkk-pick/stamp.png`, 바깥 투명) 스티커. 손잡이·배출구·트레이 x를 ±0.52로 옮겨 도장 자리를 확보했다. 렌더러는 톤 매핑 없이 팔레트 색을 그대로 쓴다.
- 캡슐: 툰 반구 + 인스턴스 잉크 외곽선 + 빛 쪽 고정 하이라이트.
- 경품: 사진 텍스처는 유지하고 셀 음영 + 외곽선. 사진이 실내광에 회색으로 찍혀 있어 밝기 배율(수건 2.6, 장바구니 1.7)을 곱한다. 컵은 몸통을 툰 유리로 바꾸고 로고만 데칼로 입혀 투명하게 보이게 한다.
- 연출: 트레이 착지와 개봉 직전에 squash & stretch, 개봉 순간 흰 플래시 + 정지 프레임(0.09초) + 카메라 흔들림 + 만화 집중선(DOM 캔버스) → 별 배지·충격파 링·연기 퍼프·외곽선 색종이(별·동그라미·세모·꼬불이)·4각 반짝이.
- UI: 잉크 테두리 + 딱딱한 그림자의 스티커 카드·버튼, 마스킹 테이프, 하프톤 점 배경, 결과 카드 도장 애니메이션.
